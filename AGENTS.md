# ToMpathy working instructions

Read the shared Agent Core instructions, then README.md and STATUS.md. The
current user's directions override older design packets. Preserve authored
essay text and image assets unless the owner explicitly requests edits.

## Standing amendments, 25 October

These are the engineering amendments requested by the October 25 engine packet.
They apply within authorized work; they grant no new research, publication,
cross-project changes, background scheduling or process ownership.

- Never idle while concrete commissioned work is implementable: take the next
  bounded item through its relevant checks. Record dependencies honestly rather
  than fabricating research or repeatedly polling an unchanged state.
- Diagnose engineering failures (crashes, dependencies, builds, timeouts, memory
  failures, tests broken by known changes), repair and rerun up to twice. Record
  repairs in the dated implementation note. A failed research gate is a result,
  remains disabled, and requires a preregistered new run before changes to prompts
  or items can be evaluated.
- When an authorized follow-up encounters a Sounding Line or Ghost result, check
  its claim ledger and open the corresponding gated ToMpathy item. Do not treat
  receipt of a file as scientific admission.
- Research badges and status text cite ledger IDs, exact public wording and
  controls from `docs/claims/SNAPSHOT.json`. When a row is absent, retain the
  source path and pin, marked “no ledger row.” GlobalFinding.claim remains prose;
  ledgerRows carries citations. Re-resolve field badges for saved readings.
- Shared research runs take priority over disposable verification. Use targeted
  serial checks, one test browser, and ownership-checked cleanup. Do not access
  a private corpus to run a new study merely because an adapter is implemented.
