# Engine v1 implementation and verification

The 0.3 beta branch adds a CPU-first Python companion and opt-in reading providers.
The Sounding Line theory review is complete. Process, local goals, governing
purpose, attention and preferences remain distinct; final text does not establish
maker choices, endorsement, human/AI contribution or a value profile.

The engine is software for research admission and evidence-preserving readings.
**This is not scientific acceptance of every milestone in the engine brief.**
No production inference admission is present. Empty estimates are deliberate.

## Implemented paths

- Canonical strict ledger, per-row provenance, compressed text, atomic Parquet
  batches, reference/time integrity and idempotent identical imports.
- Exact CoAuthor replay and handling baseline, deterministic features, pooled
  MAP fits, portable pinned model bundles and chronological evaluation.
- Capture, bounded Git/Wikipedia histories, clocked PGN and normalized panel
  imports. Decisions and corrections retain alternatives and source identities.
- Literal Q1–Q10 transcriber, local backends, pinned cache and per-question gates;
  callable correction, diagnosticity, calibration, source-use, prototype and
  governing-goal modules. Their tests do not enable production estimates.
- Packet 1.7 emission and authoritative TypeScript parity. Schema 1.7 is used
  because the reviewed frontend already occupies 1.5 and 1.6.
- Observed revision, decision and correction displays; admitted conditional
  feature-preference fits can supply population comparisons. No feature
  coefficient is relabeled as a neural drive or a broader personal value.
- Local immutable registry generation; authenticated loopback service, exact
  extension CORS, bounded requests, SSE progress, cancellation and one worker.
- Explicit None/Registry/Local provider settings, permissions, exact capture
  matching, stale-response cancellation, retained reading revisions, drive icons,
  predictability rendering and supplied Global population comparisons.
- Ghost reader-bundle bridge with pinned metadata and truth-sidecar isolation.

See [the engine guide](../engine/README.md) for commands, formats and limitations.

## Measured checks

Measurements were made locally with Python 3.13 and one CPU thread. CI targets
Python 3.12; configuring that job is not evidence of a completed remote CI run.

| Check | Observed result |
| --- | --- |
| Full pinned CoAuthor replay | 1,445 sessions, 16,998 attempted episodes, 39 exclusions, **16,959 usable decisions**, 61 writers; 64 constructed replay fixtures exact. |
| Chronology audit | Eight sessions / 104 decisions lack usable chronological order. They remain in the source census but are excluded from chronological scoring. |
| Exact baseline reproduction | 234 targets / 31 makers; maximum per-target half-Brier difference **0**. Equal-maker partial pooling **0.2944805114540165**, population **0.31020855508297623**. Runtime 17.37 seconds. |
| Full chronological handling evaluation | **16,855** eligible decisions; **129.15 seconds** on one CPU thread, below the one-hour gate. Earlier calibration data and strict time cutoffs are enforced. |
| Ghost conformance | Eight local checks: schema, references/time, truth canary isolation, exact parameter round-trip, ID/order invariance, known-answer frequency/pooling, real-shaped records and pin mismatch. These are software conformance checks, not external scientific admission. |
| Model-to-packet path | Constructed fit round-trips, admits relative feature hypotheses only under a matching test gate, rejects future training, changed inputs and wrong pins, and leaves T0 maker estimates empty. |
| Real-source packets | Owner essay T0; Distill Feature Visualization T1 (5 bounded revisions / 58 corrections); Wikipedia Empathy T1 (20 revisions / 35 corrections); internal CoAuthor T2 (12 decisions / one correction). All four validate with the extension's schema and render through reading import. |
| Live Wikipedia intake | Fetch → ingest → observed packet: **2.83 seconds** for 20 revisions. This does **not** count as the full fetch → admitted correction fit → inferred packet milestone. |
| Internal CoAuthor fit | Five choices with known selected alternatives fitted locally; other handling decisions remain observed process records. The fit is not scientifically admitted. |
| Extension/companion | Built extension opts in, authenticates to a real Python service, preserves exact capture, leaves unknown estimates empty and excludes the token from saved readings. |
| Ordinary Chrome | Chrome **155.0.8059.79**, actual **360 px native panel**. Installation, page/panel interactions, file round-trip, revision retention and full restart restoration pass with zero panel errors. No model download requested. |
| Regression suites | **125 Python tests**, **32 core tests**, and **53 browser scenarios** pass across the broad run and affected reruns. The native check and one browser scenario initially expected the old confidence percentage; their assertions now verify the relative-support label. |
| Distribution artifacts | Python wheel builds and installs into an isolated target; all ten question definitions and both license notices are present. The extension ZIP matches all 29 built files byte-for-byte and has no permanent host permission. |

The full census took 1,326 seconds. This is replay/reconstruction time, separate
from the 129-second chronological model evaluation. These timings are measurements
of this workstation and workload, not general performance guarantees.

Private source text, fitted user records, exact local paths and browser profiles
remain in ignored working folders. Only constructed packets are checked in.
Generated receipts are under ignored `evidence/` and `.local/`; none are public
research admissions. No registry was hosted and no release was published.

## Acceptance status and boundaries

| Brief milestone | Status |
| --- | --- |
| M0 ledger / replay / backbone | Numerical and performance acceptance checks pass. |
| M1 packets / registry | Software paths and all four reading imports work. Borrowed drive/value priors and explanatory goal trees await admitted population/feature inputs; real readings currently show observed history and unknown estimates. |
| M2 literal transcriber / modules | Components and constructed tests exist. Real 200-item-per-question batteries and Sounding Line admitted/inconclusive/killed records are still required. No production gate is invented from CI. |
| M3 companion | Service, cancellation, privacy and frontend work. The complete Wikipedia fetch → fit → inferred packet acceptance check remains pending admitted correction labels/model. Observational timing alone does not satisfy it. |

The correction, diagnosticity, source-use and governing-goal components are
research APIs. Their complete scientific feature-to-display pipelines are not
enabled in the ordinary companion. A supplied admission does not cause a model
download or run a new experiment. `backbone-preferences` is the implemented
admitted fit-to-packet path; its relative feature tendencies are deliberately
narrower than a drive/value interpretation.

Other explicit boundaries: history ledgers are bounded immutable snapshots;
updates need a new ledger snapshot, panel inputs require a declared normalized
field map, optional local embedding models are not downloaded or benchmarked,
and the optional full NumPyro posterior path is not implemented. The CPU MAP
path is the verified default. There is no hosted service, paid inference,
per-author language-model tuning or adoption of a maker's values.
