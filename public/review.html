Your first five-minute review

Follow these in order

  1. Open the reader beside its source

    Choose Open the guided example above. On the article, click Open Maker Reader. A native Chrome side panel should appear beside the text.

    Look for exactly three boxes: Current attention; Expertise, Habits, and Process; and Core values. The Chrome title reads “ToMpathy - What’s on the author’s mind?”

  2. Move between the text and the three sections

    Hover individual sentences. The strongest current attention shifts; new phrases grow into place and shared phrases persist. The compact reels roll to the selected sentence while the triangle stays visible. Core values stay fixed. Click a sentence to lock it, then scroll over an individual reel to explore that level. Click either green lock or double-click anywhere in the active page or reader to release it. Esc closes an open overlay first.

    Explore the continuous right-pointing hierarchy. Hover or click a block to light up its ancestors, descendants and matching page text. Directly pointing at a node stays on its visible branch; the shorter peak fades its unused final reel. Page selection can still show multiple supplied paths. The small squiggles identify groups whose order is uncertain. Attention stays empty for a parent block. Hover a value for its support wheel and sources. Hover headings for explanations; the ⋯ menu contains Help. The author/global tabs and expandable search at the bottom are interface previews; search sends no query.

  3. Check why an interpretation is there

    Click an attention phrase or core value. Read its evidence, then follow a Passage button back to the text. Uncertainty and missing evidence should remain visible.

  4. Review Options and keep a reading

    Open the ⋯ Options menu. Check author selection, context, the two planned controls, and the theme buttons. View context and timeline shows dated source statements and undated facts after collection. Export saves one file with a readable page copy and its analysis. Import reopens that copy beside the reader. Its original styling is not preserved.

    Lock “Show the iteration,” then hover a reel. Its possible sentence goals expand upward over the dimmed hierarchy. Escape closes that expansion before releasing your selection.

  5. Try a real author

    Open the real-author link above. Use Chrome’s puzzle-piece menu to select ToMpathy - What’s on the author’s mind?; pin it for next time. Clicking its toolbar icon on the article grants that page access.

    The reader should say Awaiting analysis. Options should list Simon Willison. Context can collect explicit public author links when supplied by the page. A matching result from Sounding Line is still required for estimates.

Come back whenever you like

Double-click Review ToMpathy.cmd in the project folder. It opens this same Chrome profile, builds the current code, and installs an update only when the build changed. You can close its terminal when it finishes.

Within an open review session, your bookmark brings you straight back here. After closing Chrome completely or restarting the computer, use the launcher first; it restores the extension automatically. Before installing a changed build or ending the browser session, use Options → Export if you want to keep an analysis. Captured readings are temporary.

Development tools and example revisions

Open the example with development tools, then click Open Maker Reader. The small Development tools control is only present in this testing mode. Context → Preview example revision → Accept this revision changes values to Practical care. Earlier accounts retains the original. Source capture exports, malformed packet tests, and manual context inputs also live here, outside Options.

What is working, and what is still to come?

Ready to review: the three-section reader, source capture, attribution, evidence links, context selection, imported results, revision history, and file exports.

Still to come: a connected Sounding Line service. Real pages can be captured, but they do not yet produce new estimates automatically. A matching result file is required. The bundled example supplies fictional estimates so the whole reading experience can be reviewed now.

The Datasette Lite repository is a useful companion to the real article. A repository link is context to inspect; it is not proof of an author’s goals or values.

How do updates and automated checks work?

After a code change, run Review ToMpathy.cmd again. The launcher typechecks and rebuilds before it reloads Chrome. Refresh any old article tabs, then reopen the reader. A build failure stops the update and leaves the existing installation available.

The repository’s GitHub Actions checks build, run the core and browser tests, and retain a downloadable extension ZIP for each successful run. The launcher uses this local checkout; it does not silently pull or deploy code from GitHub.

Optional: test a normal webpage with imported results

For the file-exchange path, run npm run testbed from the project folder and keep that terminal open. Visit the local test article. Click ToMpathy in the toolbar, download its first account, then use Options → Import.

This extra test uses a real HTTP page and a matching packet. It is optional for everyday interface review. Those packets only match that exact localhost article, not the bundled example or Simon’s article.

If something does not open
  • No ToMpathy icon? Use the puzzle-piece menu in this review Chrome window. Your regular Chrome profile has separate extensions. The guided example also has its own Open Maker Reader button.
  • No extension card? Run the launcher again. It verifies that Chrome reports this build enabled. A Chrome instance launched with --disable-extensions cannot serve as this test environment.
  • Wrong page or stale text? Refresh the article, click the toolbar icon there, and use Reader menu → Capture current page if needed.
  • Localhost unavailable? Only the optional HTTP testbed needs npm run testbed. This guide and the bundled example work without it.
