Your first five-minute review

Follow these in order

  1. Open the reader beside its source

    Choose Open the guided example above. On the article, click Open Maker Reader. A native Chrome side panel should appear beside the text.

    Look for “The garden designer,” the tiny ToMpathy mark, and three sections: goals, process, values.

  2. Move between the text and the three sections

    Hover different paragraphs. Goals and processes should respond; values should stay fixed. Click a paragraph to pin it. Press Esc to release it.

    Use the expand button in the process section to switch between the tree and its word cloud.

  3. Check why an interpretation is there

    Click a goal or process. Read its evidence, then follow a Passage button back to the text. Uncertainty and missing evidence should remain visible.

  4. Try a change of mind

    In the panel’s ⋯ Reader menu → Context, choose Preview example revision, then Accept this revision. Look for “Practical care” in values. Use Reader menu → Earlier accounts to inspect the original.

    This is a hand-authored fictional demonstration. It does not call an inference service.

  5. Try a real author

    Open the real-author link above. Use Chrome’s puzzle-piece menu to select ToMpathy — Maker Reader; pin it for next time. Clicking its toolbar icon on the article grants that page access.

    The header should identify Simon Willison and say Awaiting analysis. Open Reader menu → Source text to inspect the captured article and export an analysis request. Empty estimates are expected here.

Come back whenever you like

Double-click Review ToMpathy.cmd in the project folder. It opens this same Chrome profile, builds the current code, and installs an update only when the build changed. You can close its terminal when it finishes.

Within an open review session, your bookmark brings you straight back here. After closing Chrome completely or restarting the computer, use the launcher first; it restores the extension automatically. Before installing a changed build or ending the browser session, use Reader menu → Save session if you want to keep an analysis. Captured readings are temporary.

What is working, and what is still to come?

Ready to review: the three-section reader, source capture, attribution, evidence links, context selection, imported results, revision history, and file exports.

Still to come: a connected Sounding Line service. Real pages can be captured, but they do not yet produce new estimates automatically. A matching result file is required. The bundled example supplies fictional estimates so the whole reading experience can be reviewed now.

The Datasette Lite repository is a useful companion to the real article. A repository link is context to inspect; it is not proof of an author’s goals or values.

How do updates and automated checks work?

After a code change, run Review ToMpathy.cmd again. The launcher typechecks and rebuilds before it reloads Chrome. Refresh any old article tabs, then reopen the reader. A build failure stops the update and leaves the existing installation available.

The repository’s GitHub Actions checks build, run the core and browser tests, and retain a downloadable extension ZIP for each successful run. The launcher uses this local checkout; it does not silently pull or deploy code from GitHub.

Optional: test a normal webpage with imported results

For the file-exchange path, run npm run testbed from the project folder and keep that terminal open. Visit the local test article. Click ToMpathy in the toolbar, download its first account, then use Reader menu → Import result.

This extra test uses a real HTTP page and a matching packet. It is optional for everyday interface review. Those packets only match that exact localhost article, not the bundled example or Simon’s article.

If something does not open
  • No ToMpathy icon? Use the puzzle-piece menu in this review Chrome window. Your regular Chrome profile has separate extensions. The guided example also has its own Open Maker Reader button.
  • No extension card? Run the launcher again. It verifies that Chrome reports this build enabled. A Chrome instance launched with --disable-extensions cannot serve as this test environment.
  • Wrong page or stale text? Refresh the article, click the toolbar icon there, and use Reader menu → Capture current page if needed.
  • Localhost unavailable? Only the optional HTTP testbed needs npm run testbed. This guide and the bundled example work without it.
